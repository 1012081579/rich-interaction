# 按用户意图选择交互

这是一组选择依据，不是组件清单或产品内容模板。只使用任务里已存在或已授权实现的能力；每一项都可以不选。实现前先检查宿主组件是否已经提供对应行为。

## 常见匹配

| 用户需要 | 利用已有材料组织行为 | 应避免 |
|---|---|---|
| 确认输入被接收 | 触发控件的按压、选中、pending 和结果状态；就近表达变化 | 点击后沉默，或每次点击都弹全局提示 |
| 查看相关细节 | 现有展开区域、浮层或侧栏，保留触发源与上下文 | 一段短内容也强制跳页；新建冗余容器 |
| 修改当前对象 | 原位编辑，保留草稿，明确提交与取消，派生结果随确认值更新 | 输入每次变化都重建控件；失败后清空内容 |
| 缩小结果范围 | 现有搜索、筛选、选中态与结果列表共享状态，明确无结果状态 | 清空整个区域反复加载；旧响应覆盖新查询 |
| 理解对象之间的关系 | 已有列表、详情或图表共享选中对象，相关区域适度强调 | 使用不同副本导致选中和展示不一致 |
| 调整顺序或位置 | 现有拖拽、列表和布局能力，明确抓取、目标、放置与取消 | 只有“抓手”外观；拖动后实际顺序没变 |
| 调整连续值 | 现有控制器即时预览，分开临时值与提交值，必要时提供精确输入 | 指针跟随有延迟；每帧都触发昂贵持久化 |
| 等待操作完成 | 已有局部加载、状态或进度组件，保留可用上下文 | 假百分比、强制最短等待、失败也显示完成 |
| 恢复误操作 | 已有撤销或恢复能力，结果和恢复入口互相关联 | 后端无法恢复却展示撤销；所有轻微操作都二次确认 |

## 展开、浮层与渐进呈现

- 只在有相关内容和明确触发时展开。hover 预览不能成为唯一入口，也不能挡住触发源或突然夺走键盘焦点。
- 使用宿主的定位、portal、碰撞处理与层级约定。滚动或视口改变后仍能找到触发源；内容过长时在合适区域滚动，而不是跑出屏幕。
- 关闭方式遵循组件语义。需要保护未提交输入时沿用现有约定；不要为动效自行添加关闭规则。
- 返回列表或关闭详情时保留筛选、选择与合理的滚动位置。不要为了播放入场动画重置整页。

## 原位编辑与表单反馈

- 根据宿主约定确定提交时机：显式提交、失焦提交或自动保存，不能无意混用。临时编辑值与已确认值需要区别时明确分开。
- 验证提示靠近相关字段，保留输入，错误解决后及时更新。不要在用户尚未完成输入时反复报错。
- 等待和失败发生在相应操作上，避免锁住无关区域。重试使用当前有效输入，不自动恢复过期草稿。
- 保留输入法组合输入、选择区与撤销行为；快捷键处理不能截断输入法过程。

## 筛选、选择与跨区域联动

- 选中态与结果来自同一份状态；把暂时的 hover 预览与持久选择区分开。
- 请求需要节流或防抖时，输入框与本地反馈仍立即响应。使用取消或响应身份判断，防止旧结果覆盖新意图。
- 重新请求时可保留仍有意义的旧内容，但明确其正在更新；不要让旧数据呈现为新查询已完成的结果。
- 只强调受到影响的区域。用户在检查结果时不突然自动滚动到别处；确需移动视口时保留方向与上下文。

## 拖拽、重排与滑动

- 只有对象确实可移动时才增加拖动暗示。沿用现有库的传感器、键盘支持与碰撞计算，不另外实现相冲突的拖动系统。
- 从真实按下位置计算抓取偏移。被抓对象在直接操作阶段紧跟输入，不添加造成拖尾的过渡；邻居与释放后的归位可以使用过渡。
- 用稳定数据身份关联源项、占位与目标。目标指示与实际落点一致；无效释放或取消能恢复一致状态。
- 拖动距离阈值、触屏滚动方向和嵌套点击应能共存。处理指针取消、释放到区域外以及操作中视口变化，避免卡在“正在拖动”。
- 非手势入口完成同一任务，并保留焦点及可读的结果。拖拽不是绕过业务约束或确认流程的捷径。

## 异步反馈、流式结果与恢复

- 同步完成的操作直接给结果；时间未知时表达正在处理。只有数据源提供可靠进度时才显示确定百分比。
- 加载占位沿用现有内容结构，减少布局跳变；局部更新不遮盖整页。不要为了展示骨架而故意延迟已可用的内容。
- 流式数据按真实到达呈现，不通过重新播放已收到内容模拟生成。用户已经向上查看时，保留阅读位置而不是强制滚到底部。
- 取消是否能停止远端工作取决于实际能力。关闭界面、停止本地等待和撤销已提交结果是不同操作，反馈需要与事实一致。
- 乐观状态要能够回滚或重新同步。撤销入口只在实际可恢复的范围内有效；失败后用户能保留上下文并继续操作。

## 取舍

用一个问题筛掉多余设计：删除这个交互后，用户是否更难发现操作、理解变化或完成任务？若不会，通常可以省略。小范围的愉悦反馈可以保留，但不能拖慢输入、重复抢占注意力或改变组件原有含义。
